# 2026-11-06

## Goal

Start the project: collect public information on commercial text-to-SVG
models, turn the concepts into an agent-agnostic `SKILL.md`, and run
iteration 1 across five models.

## Research

Read the public product docs and four launch write-ups of a commercial
text-to-SVG model family (released 2026-09). Concepts and where each one went
in the skill: [`../features/public-concepts-to-skill-rules.md`](../features/public-concepts-to-skill-rules.md).
Key takeaways:

- Five jobs in one tool: text to SVG, references (up to 14, each given a role),
  vectorize, edit, animate.
- Quality claims are about structure: fewer control points, primitives over
  stacked paths, spacing and alignment, groups that can be animated.
- Review criteria: silhouette, geometry, prompt adherence, legibility at the
  final size.
- No public independent benchmark; we build our own task set.

### Automatic check

30 of 30 SVGs: valid XML, `viewBox` present, unique ids, nothing forbidden,
no coordinates with more than two decimals. All five animations added
`prefers-reduced-motion`.

Structure metric that separates models: share of primitives among shapes on
`vectorize` (opus 0.84, haiku 0.83, sonnet 0.39, deepseek 0.10, gpt-6-luna
0.06) and path commands (haiku 39, opus 149, sonnet 195, gpt-6-luna 642,
deepseek 1049). The skill's "primitives first" rule held on small tasks for all
models but not on the scene task for the non-Claude models.

Animation check: all five rotate `#sun-rays` about (110, 90) (two via explicit
`view-box` origin, three via `fill-box` center, which is correct here only
because the rays' bounding box is centered on the sun) and drift `#cloud`.
Reading of "drift by 6 px" split: ±3 px (opus, sonnet), ±6 px (haiku),
0→6 px (deepseek, gpt-6-luna).

### Incidents

- `claude-haiku` edited the input fixture in place during the edit task, then
  reverted it. Verified afterwards: the fixture renders pixel-identical to the
  original (ImageMagick AE = 0).
- First pi launch failed: macOS has no `timeout(1)`. The runner now falls back
  to `gtimeout` or a perl `alarm` wrapper.

### Skill feedback from the test models (merged, deduplicated)

Raised by two or more models:

1. Icon margin: the 8% default conflicts with the 24 px icon convention
   (2 units of padding, stroke reaching 1 unit from the edge).
2. Defaults "transparent background, no text" conflict with badges and tiles.
3. Edit mode: "byte for byte" conflicts with necessary consequences of the
   change (every model changed `.label` to a light color for contrast on navy).
   Unclear whether to rename replaced groups (`sun` → `moon`) and update
   `<title>`.
4. Dots in stroke icons: no pattern given; all used a small filled circle.
5. Vectorize: "4–10 regions" is unclear (colors or regions?) and too tight;
   "sample colors" assumes pixel access.
6. Deliver: "at most 5 lines" vs. edit's change list; no fixed report format.
7. Animation can only be verified as a static frame with `rsvg-convert`; opus
   used headless Chrome with a negative `animation-delay` to pause frames.

Raised once, still worth acting on:

- Never edit the input: copy it to the output path first (haiku incident).
- `transform-box: fill-box` is fragile; prefer `view-box` with an explicit
  pivot when the pivot is known.
- "Last keyframe equals the first" contradicts `alternate`.
- Recipes for crescents (two arcs) and text inside a circle (chord width).
- Reference mode: what to do when the palette lacks a needed color (water).
- After two failed repair rounds: ship and flag.
- Brief and plan feel heavy for small tasks; say when to shorten.

Mean rank over the four ranked tasks: opus 1.25, sonnet 2.50, deepseek 3.00,
gpt-6-luna 3.25, haiku 5.00.

Where the owner and the pre-review disagreed:

- sonnet's camera icon: pre-review `weak` (body line crosses the bump), owner #2.
  The pre-review weighed a geometry defect more than the owner did.
- gpt-6-luna's lighthouse: pre-review `fail` (repeating wave pattern), owner #3,
  above sonnet and haiku. A faithful composition outweighed the stylized texture.
- haiku came last on every ranked task; the pre-review gave it two `pass`.
  The pre-review grades are too coarse to separate the middle and bottom.

Lessons for the method:

- `edit` and `animate` v1 do not discriminate: every model did them well
  enough that the owner could not tell them apart. Task set v2 needs harder
  versions (several dependent changes; a motion with a non-obvious pivot or
  staggered timing).
- The ranking page saved untouched tasks in their random start order. Fixed:
  each task now records `ranked` / `tie` / `unranked`, and only dragged tasks
  count as `ranked`. The two untouched tasks above were recorded as `tie`
  following the owner's note.
- Pre-review should rank, not grade, so it can be compared with the owner's
  order.
