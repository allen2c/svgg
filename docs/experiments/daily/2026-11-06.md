# 2026-11-06

## Goal

Start the project: collect public information on commercial text-to-SVG
models, turn the concepts into an agent-agnostic `SKILL.md`, and run
iteration 1 across five models.

## Research

Read the public product docs and four launch write-ups of a commercial
text-to-SVG model family (released 2026-09). Concepts and where each one went
in the skill: [`../features/public-concepts-to-skill-rules.md`](../features/public-concepts-to-skill-rules.md).
Key takeaways:

- Five jobs in one tool: text to SVG, references (up to 14, each given a role),
  vectorize, edit, animate.
- Quality claims are about structure: fewer control points, primitives over
  stacked paths, spacing and alignment, groups that can be animated.
- Review criteria: silhouette, geometry, prompt adherence, legibility at the
  final size.
- No public independent benchmark; we build our own task set.

## Setup

### Automatic check

30 of 30 SVGs: valid XML, `viewBox` present, unique ids, nothing forbidden,
no coordinates with more than two decimals. All five animations added
`prefers-reduced-motion`.

Structure metric that separates models: share of primitives among shapes on
`vectorize` (opus 0.84, haiku 0.83, sonnet 0.39, deepseek 0.10, gpt-6-luna
0.06) and path commands (haiku 39, opus 149, sonnet 195, gpt-6-luna 642,
deepseek 1049). The skill's "primitives first" rule held on small tasks for all
models but not on the scene task for the non-Claude models.

### Incidents

- `claude-haiku` edited the input fixture in place during the edit task, then
  reverted it. Verified afterwards: the fixture renders pixel-identical to the
  original (ImageMagick AE = 0).
- First pi launch failed: macOS has no `timeout(1)`. The runner now falls back
  to `gtimeout` or a perl `alarm` wrapper.

### Skill feedback from the test models (merged, deduplicated)

Raised by two or more models:

1. Icon margin: the 8% default conflicts with the 24 px icon convention
   (2 units of padding, stroke reaching 1 unit from the edge).
2. Defaults "transparent background, no text" conflict with badges and tiles.
3. Edit mode: "byte for byte" conflicts with necessary consequences of the
   change (every model changed `.label` to a light color for contrast on navy).
   Unclear whether to rename replaced groups (`sun` → `moon`) and update
   `<title>`.
4. Dots in stroke icons: no pattern given; all used a small filled circle.
5. Vectorize: "4–10 regions" is unclear (colors or regions?) and too tight;
   "sample colors" assumes pixel access.
6. Deliver: "at most 5 lines" vs. edit's change list; no fixed report format.
7. Animation can only be verified as a static frame with `rsvg-convert`; opus
   used headless Chrome with a negative `animation-delay` to pause frames.

Raised once, still worth acting on:

- Never edit the input: copy it to the output path first (haiku incident).
- `transform-box: fill-box` is fragile; prefer `view-box` with an explicit
  pivot when the pivot is known.
- "Last keyframe equals the first" contradicts `alternate`.
- Recipes for crescents (two arcs) and text inside a circle (chord width).
- Reference mode: what to do when the palette lacks a needed color (water).
- After two failed repair rounds: ship and flag.
- Brief and plan feel heavy for small tasks; say when to shorten.

Where the owner and the pre-review disagreed:

- sonnet's camera icon: pre-review `weak` (body line crosses the bump), owner #2.
  The pre-review weighed a geometry defect more than the owner did.
- gpt-6-luna's lighthouse: pre-review `fail` (repeating wave pattern), owner #3,

- `edit` and `animate` v1 do not discriminate: every model did them well
  enough that the owner could not tell them apart. Task set v2 needs harder

  each task now records `ranked` / `tie` / `unranked`, and only dragged tasks
  count as `ranked`. The two untouched tasks above were recorded as `tie`

- Pre-review should rank, not grade, so it can be compared with the owner's
  order.

## Iteration 2: `SKILL.md` 0.2.0

### Changes in `SKILL.md` 0.2.0

| Problem in iteration 1 | Change |
| --- | --- |
| Defaults fit no asset well (8% margin on icons, transparent badges) | Asset-type table: icon / logo / badge-tile / scene, each with viewBox, background, margin, color count, text |
| haiku's fox read as a squirrel; owner ranked haiku last everywhere | Brief gets **identity cues**: 3–5 features that name the subject; check item 3 verifies each |
| Lighthouse proportions drifted; repeated wave textures (gpt-6-luna) | Plan measures the source as fractions; "natural textures" rule: varied irregular shapes, no repeated patterns |
| Camera bump drawn across the body (sonnet, deepseek) | Outline-icon rule: inner lines do not cross outlines |
| Vectorize color budget unclear, sampling assumed pixels | 6–16 colors for scenes, patch-average command, color bands planned by y range |
| Cutout through one layer only (opus repair) | Do not cut holes through one layer; draw on top |
| Edit: byte-for-byte vs forced side effects; haiku edited the input | Never modify the input; forced side effects allowed and reported; move groups with `translate` |
| Pivot via `fill-box` correct only by luck | Known pivot → `view-box` + explicit px origin |
| "Seamless" vs `alternate`; start pose varied (−6 px) | First frame equals the input; "moves N and back" = 0 → N → 0; phase offsets without breaking frame 0 |
| No motion verification | Headless browser paused frames, or hand-trace one point per group |
| Reports not comparable | Fixed 6-line report template |
| Crescent, star, cloud, text-in-circle cost time | Recipes section (crescent path verified by render) |
| Brief felt heavy for icons | Small assets need only three brief lines; plan need not appear in the answer |

### Skill feedback (iteration 2, merged)

- Edit: no rule for an added part hidden by existing layers, or a move that
  creates new overlaps (blade over cloud, tower into the hill).
- Large textures: "3–9 shapes per area" is too few for a 960 px rock field;
  is generating coordinates with a script acceptable?
- Full-bleed shapes that cross the viewBox edge should be allowed.
- Durations: say whether "1.2 s" is a full cycle (all assumed yes).
- Phase offset with a fixed first frame: a positive delay makes the part
  idle for half a cycle; offer phase-shifted keyframes that start at rest.
- Freeze-frame preview: the override delay is the element's own delay
  minus T.
- Compare with the source by stacking both in one image.

### Owner direction for iteration 3

Reference images must be more diverse. Iteration 3 replaces the tied tasks
with tasks built on different reference types.

### Changes in `SKILL.md` 0.3.0

What the owner rewards, read from the disagreements:

- **Detail and finish.** deepseek, which spends the most time, came first
  on the lighthouse, teapot, and nutmeg.
- **Tonal form** (iteration 2 lighthouse) over saturated flat color.
- **A style applied consistently.** On the heron, the owner put gpt-6-luna
  first (dark outlines everywhere, curled foam motifs) and the orchestrator
  put it last; the orchestrator weighed bird anatomy, the owner weighed
  whether the whole image reads as a print.

Regressions and conflicts found:

- The 0.3.0 cloud recipe (rounded rect plus circles) produced bubble clouds
  on the lighthouse for haiku and opus.
- "Never tile textures" conflicts with woodblock waves, which are repeated
  curls by design (haiku).
- `textLength` is ignored by `rsvg-convert` 2.63.3 (verified against
  headless Chrome); two models lost time on it.
- Pose roles had no mapping from the reference to the canvas (opus).

### Skill feedback (iteration 3, merged)

Recipes asked for: organic cloud outline, tube parts (spout, handle, stem),
leaf with veins, scripted rocks by depth, `textPath` banner, color sampling
on flat areas only, 50% overlay compare. Rules asked for: style roles
override the generic volume and texture rules; poster or print asset row;
badge banners may overlap the ring; repair triage order; higher gradient
budget for glossy products.
